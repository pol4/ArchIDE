# ArchIDE — предложение по редизайну интерфейса

Цель: **максимум места графу и аспектам**, вторым приоритетом — диалог с агентом, всё
остальное — по требованию. Вызов аспектов и любых представлений — **от самого элемента
графа**; создание и правка сущностей — тоже от элемента (или от канваса, если новое
ни к чему не привязано). Граф — «дом», куда всегда возвращаешься.

Документ содержит три варианта дизайна, сравнение, рекомендованный гибрид и поэтапный
план внедрения. Реализация — после согласования (AGENTS.md п.3: изменения сценариев/UI
согласуются до кода).

---

## 1. Что не эргономично сейчас

- **Сайдбар 340 px всегда открыт** и занимает ~25 % ширины; на канвас остаётся ~1100 px
  при 1440 px экрана. Девять панелей идут одной лентой, к операциям нужно скроллить.
- **Аспекты живут отдельно от элементов**: селектор аспекта + кнопка `⧉` открывают окно
  поверх канваса; чтобы понять, «где этот узел участвует», нужно перебирать аспекты руками.
- **Операции оторваны от контекста**: работа с элементом (правка, задание, метки,
  кодогенерация, приёмка) живёт в панели **9**, а не у самого элемента; приходится копировать
  id в поле *Node*.
- **Плавающие окна** перекрывают граф, их позиции не сохраняются, при нескольких окнах
  начинается «стопка».
- **Статус/лента** — отдельная панель внизу сайдбара, при этом лента — самый нужный элемент
  при прогоне.

## 2. Принципы

1. **Graph-first.** Канвас — основная поверхность и точка возврата; он никогда не
   «сжимается» ради панелей.
2. **Element-centric.** Любое действие доступно **на элементе**: клик по узлу → панель
   элемента (свойства, аспекты, действия). Создание «внутри» — там же; создание «рядом» —
   по канвасу.
3. **Aspects as lenses.** Аспект — не отдельное окно, а **режим отображения** всего канваса
   с фокусом на выбранном элементе: переключение мгновенное, контекст (уровень, фокус)
   сохраняется, «назад к C4» — одна кнопка.
4. **Progressive disclosure.** Настройка, реконструкция, генерация, приёмка — по требованию:
   модальный мастер, выдвижные панели, командная палитра.
5. **Agent as co-pilot.** Диалог — всегда под рукой (плавающая панель/вкладка), и он знает
   **текущий контекст** (выбранный элемент, аспект, уровень) без ручного ввода id.
6. **Ничего не теряется.** Все текущие возможности остаются, меняется только способ доступа.

## 3. Вариант A — «Canvas-first + командная палитра»

Полноэкранный канвас, тонкий верхний бар, всё остальное — drawers и палитра.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ ArchIDE   TripApproval ▾   [C4 ▾][Аспекты ▾]  L2 ▾  ↑↓  🔍 find   ⟳ Rerun  ⌘K │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│                            К А Н В А С   Г Р А Ф А                           │
│                    (максимум площади, аспект-линзы прямо здесь)              │
│                                                                              │
│        ┌────────────┐      ┌────────────┐        ┌─────────────┐             │
│        │ Trip API ⊕ │─────▶│ Approvals  │───────▶│ PostgreSQL  │             │
│        └────────────┘      └────────────┘        └─────────────┘             │
│                                                                              │
│                                                        ┌──────────────────┐  │
│                                                        │ Агент  ▁         │  │
│                                                        │ > добавь кеш…    │  │
│                                                        └──────────────────┘  │
└──────────────────────────────────────────────────────────────────────────────┘
   drawers по требованию: ⚙ настройки · 📦 артефакты · ✅ валидация · 📜 лента
```

- **Клик по элементу** → маленькое **радиальное меню** у узла: *Аспекты · Правка ·
  Создать внутри · Связать · Задание/Метки · Удалить*. Выбор «Аспекты» показывает список
  аспектов, в которых элемент участвует, — выбор переводит канвас в аспект-линзу.
- **Клик по пустому месту** → меню канваса: *Создать узел · Создать связь · Вставить*.
- **⌘K / Ctrl+K** — командная палитра: все операции (реконструкция, валидация, метрики,
  work package, метки, кодогенерация, дифф, экспорт) с поиском по названию.
- **Агент** — плавающая панель в правом нижнем углу (разворачивается на пол-экрана),
  автоматически подставляет контекст выделения.
- Плюсы: максимум графа, мышь почти не нужна; минусы: радиальные меню надо освоить,
  на маленьких экранах палитра важнее меню.

## 4. Вариант B — «Inspector + Aspect lens» (рекомендуемый)

Канвас на весь экран; справа — **инспектор элемента** (появляется по клику) и вкладка
**Агент**; настройки/реконструкция — модальный мастер.

```
┌────────────────────────────────────────────────────────────┬─────────────────┐
│  TripApproval ▾   [C4][Interface][Data][Behavior][Process] │  ИНСПЕКТОР      │
│  L2 ▾  ↑↓  🔍  ⟳  ⤓ all                                   │  Trip API       │
├────────────────────────────────────────────────────────────┤  Component      │
│                                                            │  ─────────────  │
│                     К А Н В А С   Г Р А Ф А                │  Аспекты:       │
│                                                            │  • structure    │
│         ┌────────────┐   ┌────────────┐                    │  • interface(4) │
│         │ Trip API ● │──▶│ Approvals  │                    │  • data(3)      │
│         └────────────┘   └────────────┘                    │  • quality(1)   │
│                                                            │  ─────────────  │
│                                                            │  Действия:      │
│                                                            │  ✎ правка       │
│                                                            │  ＋ внутри      │
│                                                            │  🔗 связать     │
│                                                            │  📦 задание     │
│                                                            │  🏷 метки       │
│                                                            │  ⌫ удалить      │
│                                                            ├─────────────────┤
│                                                            │  АГЕНТ          │
│                                                            │  контекст: Trip │
│                                                            │  > добавь кеш…  │
└────────────────────────────────────────────────────────────┴─────────────────┘
```

- **Клик по элементу** → инспектор: имя/тип/evidence, **чипы аспектов** (с количеством
  связанных элементов) и **действия** (правка, создание внутри, связь, задание, метки,
  генерация для этого элемента, удаление).
- **Клик по чипу аспекта** → **аспект-линза**: канвас перерисовывается в нотации аспекта
  (C4/API/ER/state/BPMN/sequence/…) с фокусом на элементе; сверху — чипы аспектов и
  «← к C4». Фокус, уровень и зум сохраняются при переключении.
- **Клик по канвасу** → «создать узел / создать связь / вставить».
- **Агент** — вкладка под инспектором: тот же чат, но с автоматическим контекстом
  («выделено: `component://trip/api`», активный аспект, уровень) и кнопкой
  «применить как транзакцию».
- **Настройки и реконструкция** — модальный мастер (`R` или кнопка ⟳): репозиторий, LLM,
  runner, бюджет контекста, том агента — с проверкой соединения.
- **Генерация/приёмка** — из инспектора (для элемента) или из мастера (для модели целиком).
- Плюсы: граф на весь экран, аспекты — в один клик и всегда в контексте элемента, агент
  рядом и «знает» контекст; минусы: инспектор занимает 320–360 px, когда открыт (но
  закрывается одним кликом/`Esc`).

## 5. Вариант C — «Workspace с вкладками»

Одна рабочая область, вкладки на весь экран: **Graph · Aspect · Agent · Report**.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ [ Graph ] [ Aspect: state ] [ Agent ] [ Report ]        TripApproval ▾   ⌘K  │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│                        активная вкладка на весь экран                        │
│              (Graph = C4, Aspect = нотация выбранного аспекта)               │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘
```

- Из графа элемент «отправляется» в аспект-вкладку (`→ Aspect`), из аспекта — обратно.
- Агент и отчёты (валидация/метрики/приёмка) — отдельные полноэкранные вкладки.
- Плюсы: ничего не перекрывается, удобно для больших моделей и отчётов; минусы:
  переключение вкладок вместо мгновенной линзы, слабее «аспект как свойство элемента».

## 6. Сравнение

| Критерий | A (canvas+палитра) | **B (inspector+lens)** | C (вкладки) |
|---|---|---|---|
| Площадь графа | максимум | максимум (инспектор закрывается) | максимум на вкладке |
| Доступ к аспектам от элемента | радиальное меню | **чипы аспектов в инспекторе** | отправка в вкладку |
| Правки/создание | меню у узла/канваса | **инспектор + канвас** | вкладка Graph |
| Агент | плавающая панель | **вкладка под инспектором с контекстом** | отдельная вкладка |
| Отчёты (валидация/метрики/приёмка) | drawer | drawer/мастер | **вкладка Report** |
| Кривая обучения | средняя | **низкая** | низкая |
| Стоимость реализации | средняя | **средняя** | высокая (переработка раскладки) |
| Риск сломать текущие тесты | средний | **низкий (ids сохраняем)** | высокий |

## 7. Рекомендация: гибрид **B + элементы A/C**

- База — **вариант B** (канвас на весь экран + инспектор элемента + аспект-линза + агент
  рядом). Он прямо реализует все ваши требования и дешевле C.
- Из **A** берём **командную палитру** (`⌘K`) — она закрывает доступ к «редким» операциям
  без раздувания панелей.
- Из **C** берём **вкладку «Report»** (валидация, метрики по аспектам, конформанс, дифф
  приёмки) — отчётам нужен полный экран.
- Настройки/реконструкция — **модальный мастер**; лента событий — **drawer снизу**
  (появляется во время прогона, прячется сама).

### Модель взаимодействий (единая для всех поверхностей)

| Действие | Что происходит |
|---|---|
| Клик по узлу/ребру | инспектор: свойства, **чипы аспектов**, действия |
| Клик по чипу аспекта | аспект-линза всего канваса с фокусом на элементе; «← к C4» |
| Клик по пустому канвасу | «создать узел / связь / вставить» (новое, ни к чему не привязанное) |
| Двойной клик по узлу | внутрь (следующий уровень) — как сейчас |
| `Esc` | закрыть инспектор/линзу → полный C4 |
| `A` / `E` / `Space` | аспекты / правка / агент для выделенного |
| `⌘K` | командная палитра (все операции) |
| `R` | мастер реконструкции |
| `,` / `.` | листать вид внутри активной линзы |
| Перетаскивание | панорама; колесо — зум (как сейчас) |

### Что убираем с постоянного экрана

| Было | Стало |
|---|---|
| Панели 1–4 (репозиторий, LLM, контекст, том) | модальный мастер `R` |
| Панель 5 (slice) | тулбар канваса (там уже level/levels) + `⌘K` |
| Панель 8 (generate) | инспектор элемента / мастер / `⌘K` |
| Панель 9 (architect) | инспектор элемента + вкладка Report + `⌘K` |
| Status/лента | drawer снизу (авто-появление при прогоне) |
| Плавающие аспект-окна | аспект-линза канваса |

## 8. План внедрения (по шагам, с тестами на каждом)

Каждый шаг — отдельный блок: браузерные тесты **до** реализации, затем прогон
`tests/run_e2e.sh`.

1. **UI-1. Полноэкранный канвас + тулбар.** Сайдбар сворачивается; настройки уезжают в
   модальный мастер (ids сохраняем, чтобы не ломать тесты); лента — drawer снизу.
2. **UI-2. Инспектор элемента.** Клик по узлу → свойства + **чипы аспектов** + действия
   (правка, создание внутри, связь, удаление). Тесты: клик по узлу открывает инспектор;
   «создать внутри» добавляет дочерний узел нужного типа; «связать» проводит ребро.
3. **UI-3. Аспект-линза.** Чип аспекта переводит канвас в нотацию аспекта с фокусом на
   элементе; «← к C4» возвращает; фокус/уровень сохраняются. Плавающие окна остаются как
   «второй экран» (по желанию) или убираются.
4. **UI-4. Агент-панель с контекстом.** Вкладка агента рядом с инспектором: контекст
   выделения, история, «применить как транзакцию».
5. **UI-5. Командная палитра `⌘K` + вкладка Report.** Все операции из палитры; отчёты
   (валидация, метрики по аспектам, конформанс, дифф приёмки) на полный экран.
6. **UI-6. Доводка.** Горячие клавиши, сохранение состояния (модель, линза, уровень,
   размер инспектора), тёмная тема, скриншоты гайда переснять (`ARCHITECT_GUIDE_UI.md`).

Оценка: UI-1…UI-3 — ядро (даёт «максимум графу + аспекты от элемента»), UI-4…UI-6 —
доводка. Тесты: ~6–10 новых браузерных проверок на шаг; существующие проверки сохраняются
(ids и API не меняются), гейт остаётся зелёным на каждом шаге.

## 9. Открытые вопросы

1. Какой вариант берём за основу — **B (рекомендую)**, A, C или гибрид?
2. Плавающие аспект-окна: убрать совсем или оставить как «второй экран» для сравнения
   двух аспектов рядом?
3. Нужна ли тёмная/светлая тема в этом же блоке или отдельным пунктом?
