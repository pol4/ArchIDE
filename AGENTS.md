# Правила для агента (ArchIDE)

Обязательные правила работы над этим репозиторием. Нарушение = работа не считается
завершённой.

## 1. Сквозной e2e после крупных доработок (обязательно)

- После **каждой достаточно крупной доработки** запускай сквозной e2e:
  ```bash
  bash tests/run_e2e.sh
  ```
- Прогон включает **оба режима**: **API** (`tests/api/test_api.py`) и **браузер**
  (`tests/browser/test_ui.mjs`, headless Chrome, реальные действия пользователя).
- **Фиксируй результат** прогона (pass/fail и число проверок) в отчёте о работе /
  описании PR. Крупную доработку не завершай с красным e2e.
- Если e2e красный по внешней причине (нет Chrome/сети) — явно укажи это и что
  именно не удалось прогнать.

## 2. Тесты — ДО реализации новой функциональности (обязательно)

- Для **любой новой функциональности** **сначала добавь тесты** (и API, и браузерные,
  где применимо), фиксирующие ожидаемое поведение, и только **потом** реализуй её.
  До реализации новые тесты должны падать («red»).
- Функциональность без тестов, написанных **до реализации**, не считается готовой.
- Если у функциональности пока нет UI-поверхности — браузерный тест не добавляется, но
  это **фиксируется**; при появлении поверхности тест добавляется **до** реализации.
- Обновляй `SCENARIOS.md`: добавляй/правь сценарий и его покрытие тестами.
- Тесты держи **детерминированными**: `mode=mock`, `runner=local`, стаб-docker
  (`tests/stub/docker`), фиксированные фикстуры, изолированный конфиг. Реальный
  Docker и внешний LLM в тестах не использовать.

## 3. Согласование сценариев и тестов

- Набор сценариев (`SCENARIOS.md`) и подход к тестам **согласуется с пользователем**.
- Перед добавлением/изменением состава сценариев — сначала предложи и дождись
  согласования, затем фиксируй в `SCENARIOS.md` и покрывай тестами.

## 4. Синхронность документации

- Изменения, затрагивающие концепцию/архитектуру, отражай в `Concept.md`,
  `ARCHITECTURE.md`, `ROADMAP.md` (и в `SCENARIOS.md` при изменении сценариев).
- Держи сквозную нумерацию разделов концепции согласованной во всех документах.

## 5. Порядок работы над крупной задачей

1. Согласовать сценарии/тесты (если меняются).
2. **Добавить тесты** под новую функциональность (API + браузер, где применимо) —
   до реализации они должны падать («red»).
3. Реализовать изменение.
4. Обновить `SCENARIOS.md`.
5. Прогнать `bash tests/run_e2e.sh` → зафиксировать результат (все тесты зелёные).
6. Обновить документацию и (по запросу) закоммитить/запушить.
