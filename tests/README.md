# ArchIDE — e2e тесты

Сквозные тесты сценариев из [`../SCENARIOS.md`](../SCENARIOS.md) в двух режимах:
**API** (HTTP) и **браузер** (headless Chrome, реальные действия пользователя).

## Запуск

```bash
bash tests/run_e2e.sh          # из корня репозитория
```

Скрипт:

1. создаёт изолированную конфигурацию (`ARCHIDE_DATA` во временном каталоге);
2. кладёт на `PATH` **стаб-docker** (`tests/stub/docker`) — реальный Docker не нужен;
3. поднимает сервер `archide-poc/server.py` в детерминированном профиле
   (`mode=mock`, `runner=local`), печатает логи в временный файл;
4. запускает API-набор (`tests/api/test_api.py`) и браузерный набор
   (`tests/browser/test_ui.mjs`);
5. печатает `E2E RESULT: PASS|FAIL` и возвращает код выхода.

Порт по умолчанию `8901` (переопределяется `ARCHIDE_TEST_PORT`). Chrome берётся из
`$CHROME` или ищется среди `/usr/bin/google-chrome`, `/snap/bin/chromium`, …

## Структура

```
tests/
  run_e2e.sh            оркестратор
  stub/docker           стаб docker (volume/run/logs/rm; опц. задержка для cancel)
  fixtures/sample_repo  детерминированный репозиторий для реконструкции
  api/test_api.py       API e2e (Python stdlib, без зависимостей)
  browser/
    package.json        зависимость puppeteer-core
    test_ui.mjs         браузерный e2e
```

## API-набор (`tests/api/test_api.py`)

Python stdlib (`urllib`), без внешних зависимостей. Покрывает: реестр агентов,
конфиг (round-trip + запись на диск), реконструкцию (single/two-pass), события
запуска, отмену, валидатор (инструмент + схему), том, авторизацию шлюза, проброс
ошибок, демо-фикстуру.

## Браузерный набор (`tests/browser/test_ui.mjs`)

`puppeteer-core` + системный Chrome. Эмулирует действия пользователя: ввод адреса,
выбор агента/режима, клики, ожидание результата, drill-down по клику мышью,
переключение фильтров источников, проверки DOM/рендера.

Первый запуск ставит `puppeteer-core` (`npm install` в `tests/browser/`); Chromium
не скачивается (используется системный Chrome).

## Правила сопровождения (обязательно)

- **Тесты — ДО реализации**: для новой функциональности **сначала** добавляются тесты
  (API и браузер, где применимо), фиксирующие ожидаемое поведение («red»), и только
  **затем** реализация; + обновление `SCENARIOS.md`.
- Тесты **детерминированы**: mock/local/stub-docker, фиксированные фикстуры,
  изолированный конфиг.
- Сквозной прогон обязателен после каждой достаточно крупной доработки
  (см. `../AGENTS.md`).

## Добавить тест

- **API:** добавьте проверку в `tests/api/test_api.py` (`check(...)`).
- **Браузер:** добавьте шаг в `tests/browser/test_ui.mjs` (`runDemo`/`runLive`).
- **Сценарий:** опишите в `SCENARIOS.md` (согласование) и сошлитесь на тесты.
